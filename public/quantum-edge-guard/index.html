What v1 does — all runnable today

Four jobs, done locally

Quantum Edge Guard grades the crypto on your machines and the endpoints they talk to. Its grading approach grows out of what the lab learned building snoot — snoot inventories the crypto in your code; qeg grades the crypto on your machines.

01 — LOCAL POSTURE AUDIT qeg scan

Audit this machine

Reads the crypto configuration already on the machine — SSH client/server configs and OpenSSL config — and grades what it finds.

  • Weak or classical-only key exchange, legacy ciphers and MACs, permissive TLS floors
  • Lists listening TCP services and flags plaintext FTP / Telnet / HTTP exposure
  • Every finding cited by file and line
02 — ENDPOINT GRADING qeg check <host[:port]>

Grade what was actually negotiated

Opens a real TLS handshake to the endpoint and grades what was negotiated — not what the endpoint claims to support.

  • Protocol version, cipher suite, key-exchange group, certificate signature family
  • Classical-only key exchange grades WARN — quantum-vulnerable
  • Post-quantum hybrid grades PASS; TLS below 1.2 grades FAIL
03 — POLICY ENFORCEMENT --policy <file>

Set a floor, and hold it

A small local policy file sets your floor: minimum TLS version, whether post-quantum key exchange is required, and a deny-list of hosts the guard refuses to pass.

  • Violations print POLICY FAIL and exit non-zero
  • Exit codes: 0 clean · 1 FAIL findings · 2 policy violation
  • Made to gate scripts, cron, and CI
04 — REPORTING qeg report

A graded report you keep

Every run prints a graded plain-text report — PASS / WARN / FAIL / POLICY FAIL — with an evidence line for each grade.

  • Stable, parseable line shapes
  • No telemetry, no phone-home, no account
  • qeg report prints the policy format and an example policy

Certificate grading reads the leaf signature family too — RSA / ECDSA / Ed25519 today are flagged as classical (Shor-vulnerable long-term); ML-DSA / SLH-DSA are recognised by OID so the grader is ready before such certificates are common.

Proof — real verified runs

It has already run. Here is what it found.

These are the founding verification runs — the same build that is on main today. Output below follows the tool's real report format.

qeg check — real TLS 1.3 handshake, graded end to end exit 0 — warnings, no failures
$ qeg check <local TLS endpoint> qeg check — TLS endpoint [PASS ] tls version — negotiated TLS 1.3 [INFO ] cipher suite — negotiated suite recorded in report [WARN ] key exchange — X25519 — classical key exchange: harvest-now-decrypt-later applies [WARN ] certificate — leaf signature: RSA (classical signature) — Shor-vulnerable family; migration to ML-DSA required long-term summary: 1 pass, 1 info, 2 warn, 0 fail, 0 policy-fail

What this proves: the handshake is real, and the grading is honest — a modern TLS 1.3 endpoint still grades WARN on the quantum question, because X25519 and RSA are classical. An endpoint that negotiates a PQC hybrid (X25519+ML-KEM) grades PASS instead.

qeg scan — planted weak SSH config, caught with file:line exit 1 — FAIL findings
$ qeg scan qeg scan — local crypto posture [FAIL ] ssh kex — /etc/ssh/sshd_config:12 offers known-weak key exchange: diffie-hellman-group14-sha1 [FAIL ] ssh ciphers — /etc/ssh/sshd_config:18 enables broken ciphers: 3des-cbc [FAIL ] ssh macs — /etc/ssh/sshd_config:21 enables broken MACs: hmac-md5 summary: findings at FAIL level — see file:line above for each fix

What this proves: classical configuration rot — the settings automated attack tooling exploits first — is found precisely, with the file and line cited, not waved at.

qeg check --policy — deny-listed host refused before connecting exit 2 — POLICY FAIL
$ qeg check <deny-listed host> --policy qeg.policy qeg check — policy enforcement [POLICY FAIL] policy block-list — host is on the policy deny_host list — check refused before connecting summary: 0 pass, 0 info, 0 warn, 0 fail, 1 policy-fail

What this proves: policy is enforcement, not advice. A denied host is refused before any connection is made — and the exit code lets your scripts and CI stop on it.

Install

Build it from source

Rust. No runtime services, no account, no network access needed except the endpoints you explicitly ask it to check.

Build — Cargo
# clone the repo, then:
cargo build --release
# binary: target/release/qeg
# package name: quantum-edge-guard
  • qeg scan Audit this machine — SSH + OpenSSL posture, listening services.
  • qeg check example.com Grade an endpoint (port 443) — real handshake, negotiated crypto.
  • qeg check mail.example.com:993 Grade a specific port.
  • qeg check example.com --policy qeg.policy Grade against your policy floor — violations exit 2.
  • qeg check 192.168.1.10:8443 --insecure Self-signed / internal endpoint: crypto graded, identity not verified — the report says so, loudly.
  • qeg report Print the policy format and an annotated example policy.

Honest limits

What it does not do

This section is the product's stance, not fine print. A guard you over-trust is worse than no guard.

It does not make any machine unbreakable

And no version of this product will ever honestly claim to. It finds and grades weak cryptography and enforces the policy you set — it is not a magic shield.

v1 does not intercept or proxy traffic

The enforcement proxy is on the roadmap (v2) — it is not in v1. In v1, enforcement is real at the level a terminal tool can honestly enforce: scripts, cron, and CI that call qeg stop on a policy violation.

It does not patch your software

It tells you, precisely, what to fix — with the file, line, and negotiated evidence. Fixing it stays in your hands, on your schedule.

Read “classical negotiated” correctly

The probe grades what it negotiates. “Classical negotiated” means the endpoint accepted a classical handshake from this probe — read it as “quantum-vulnerable unless the endpoint also offers PQC and prefers it,” and see the report notes for each endpoint.
