Field test — a real project

Scanning Magic Box: what the scanner found, and what it missed

snoot was also run over Magic Box, the author's own AES-256-GCM file container with an embedded Rivest–Shamir–Wagner time-lock. The honest result is the point:

Automated pass

MEDIUM  SNOOT016 — a classical-crypto dependency flagged in the codebase.

Manual review pass

HIGH  3072-bit RSA key generation for the RSW time-lock — caught by a human, missed by the scanner.

And the manual finding came with the uncomfortable part stated plainly: Shor's algorithm would collapse that time-lock, and there is no drop-in NIST replacement for it. A report that only lists easy swaps isn't an inventory. This one tells you where there's no swap to make.

The manual pass catches what the scanner misses. That's the differentiator — and it's in every scan.

Honest limits

What snoot does not do

Stated up front, because a scan you over-trust is worse than no scan.

Heuristic discovery, no data-flow analysis

snoot finds crypto by pattern and structure. A flag means “look here” — not “this is exploitable.” Severity is triage guidance, not a vulnerability verdict.

Source only in v1

The scan covers source code and config you send. No binaries, no containers, no firmware in v1 — if it isn't source, it isn't scanned.

Obfuscation can hide crypto

Obfuscated or dynamically loaded cryptography can be missed by the automated pass. The manual pass exists to narrow that gap — it does not close it to zero, and the report won't pretend otherwise.
